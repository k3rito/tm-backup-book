## 2025-02-15 - Progress Flush Bottleneck and RSS Metric Call Redundancy
**Learning:** In the `TransferService._flush_completed` loop, calling the async `_persist_progress_state()` on every sequential message popped was an O(N) operation per batch. This led to redundant local file reads/writes and multiple slow network requests to Cloudflare R2 for intermediate states. In addition, querying `current_rss_bytes()` multiple times per logging statement in `transfer.py` coupled with lazy but uncached imports/instantiation of `psutil.Process()` caused unnecessary CPU overhead.
**Action:** Always batch persistence operations outside of sequence-processing loops to turn O(N) disk/network writes into O(1). Cache global process-related variables like `psutil.Process()` and compute repetitive metrics once before logging to minimize runtime and system query overhead.
