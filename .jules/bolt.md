## 2025-03-05 - Optimize Progress State Persistence & Process Memory Profiling
**Learning:** In pipelines processing sequences of messages (flush loops), persisting status updates synchronously on every iteration creates an O(N) overhead bottleneck due to redundant network/file writes. Batching state persistence at the end of the flush block reduces this to O(1) complexity. Additionally, repeatedly importing `psutil` and re-initializing `psutil.Process()` to check RSS memory usage on logging loops creates significant micro-overhead that can be eliminated by caching the process object globally.
**Action:** Always buffer database, file, and network writes outside sequential loops. Cache performance-profiling system process handles globally instead of recreating them on every loop cycle.
