## 2025-02-12 - Optimize Progress Persistence and Memory Caching Overhead
**Learning:** Progress persistence to local disk and remote R2 S3 storage inside consecutive loops creates an $O(N)$ overhead where $N$ is the number of processed messages in a batch. Extracting state persistence to be executed outside the loop achieves $O(1)$ complexity, reducing network requests. Additionally, calling `psutil.Process()` and importing `psutil` on every memory snapshot results in high system call overhead; caching the Process handle globally lazily yields a ~2.6x performance boost for RSS checks, and pre-calculating the RSS value once per log event avoids redundant queries.
**Action:** Always verify if I/O or system call operations are inside loop sequences and batch them, and globally cache process-specific handles that query system parameters.
