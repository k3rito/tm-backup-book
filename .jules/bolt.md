## 2025-02-15 - Batching S3/R2 State Persistence Outside of Processing Loops
**Learning:** Sequential processing loops that update and write checkpoint state often create severe I/O bottlenecks. In this architecture, calling `_persist_progress_state()` inside the contiguous `_flush_completed` loop resulted in $O(N)$ local file and Cloudflare R2 S3 network uploads. By moving state synchronization to the end of the flush operation, we transition state updates to $O(1)$ complexity, avoiding multiple redundant API requests and local I/O operations while maintaining progress tracking accuracy.
**Action:** Always audit event loops and pipeline flush methods for repeated internal disk or network persistence calls. Batch state writes and remote synchronizations to execute once at the end of transactional blocks rather than at individual iterations.
