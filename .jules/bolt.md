## 2024-10-31 - [N+1 State Persistence and Process Cache]
**Learning:** In the progress synchronization loop (`_flush_completed`), calling `_persist_progress_state` (which uploads state to Cloudflare R2 and writes to local disk) on every individual message sequence commit is an O(N) bottleneck that severely impacts performance and cost under load. Moving persistence out of the loop batches updates to O(1) per flush without compromising resume accuracy. Additionally, instantiating `psutil.Process()` on every `current_rss_bytes()` utility call incurs redundant object creation and library lookup overhead, which can be avoided entirely by lazily caching the Process object globally.
**Action:** Always batch I/O and remote cloud storage uploads outside of sequential loops. Ensure resource-heavy system metric query objects are cached globally rather than re-instantiated on every call.
